# Reports and Finding Lifecycle

Learn how `security-review` tracks findings across commits using deterministic SHA-256 fingerprints, generates multi-format report artifacts, and manages lifecycle states.

---

## Deterministic Fingerprinting

Every finding generated by `security-review` receives a stable, reproducible **fingerprint**:

```text
Fingerprint = SHA-256( Rule_ID + "|" + Relative_File_Path + "|" + Normalized_Code_Snippet )
```

### Why Fingerprints Matter

- **Refactoring Resilience**: Line numbers and file positions change during edits. Normalized fingerprinting ensures a finding remains recognizable even if code above or below it moves.
- **CI Alert Deduplication**: GitHub Code Scanning and baseline comparators use fingerprints to track whether an issue is new, existing, or resolved.

---

## Finding Lifecycle States

When evaluated against a baseline snapshot (`.security-baseline.json`), each finding is categorized into one of three states:

1. **New**: Introduced in the current commit or scan scope. Evaluated strictly by `--new-only` CI gates.
2. **Existing**: Previously recorded in the baseline snapshot. Permitted under gradual adoption policies.
3. **Resolved**: Recorded in the baseline but no longer present in source code.

---

## Report Formats

`security-review` outputs a human-readable terminal summary to stdout and writes structured artifacts via `--format`:

| Format | Artifact Flag | Typical Usage |
| :--- | :--- | :--- |
| **JSON** | `--format json` *(default)* | Machine parsing, baseline creation, custom dashboards |
| **SARIF** | `--format sarif` | GitHub Code Scanning tab, OASIS standard analyzers |
| **JUnit** | `--format junit` | CI test dashboard integration (Jenkins, GitLab CI) |

```sh
# Generate SARIF artifact for GitHub Actions
security-review scan --format sarif --output results.sarif
```
