# Reports & Finding Lifecycle

Understand how `security-review` formats scan reports, calculates deterministic finding fingerprints, tracks issue lifecycles, and manages baselines versus suppressions.

## Supported Output Formats

| Format | Flag | Ideal Use Case |
| :--- | :--- | :--- |
| **Terminal** | `--format terminal` | Interactive local developer CLI output with color-coded severity. |
| **JSON** | `--format json` | Machine-readable integration for custom pipelines and automated parsing. |
| **SARIF** | `--format sarif` | GitHub Security Code Scanning tab & OASIS SARIF v2.1.0 compatible tools. |
| **JUnit XML** | `--format junit` | CI test dashboard integration (Jenkins, GitLab CI, CircleCI, Azure DevOps). |

```sh
# Export scan findings as SARIF for GitHub Security tab
security-review scan --format sarif --output results.sarif
```

## Fingerprints & Finding Lifecycle

Every security finding generated by `security-review` receives a deterministic **fingerprint**.

### Finding Lifecycle States

1. **New**: Introduced in the current commit or scan scope.
2. **Existing**: Present in both current scan and recorded baseline.
3. **Resolved**: Recorded in baseline but no longer detected in source code.

## Baselines vs. Suppressions

It is vital to distinguish **baselines** from **suppressions**:

### Baselines (`--baseline <file>`)
A **baseline** is a snapshot of all pre-existing findings in a codebase. It is designed for gradual scanner adoption in legacy repositories, allowing developers to block *new* issues while deferring legacy technical debt remediation.

```sh
# Generate baseline snapshot
security-review scan --format json --output .security-baseline.json

# Enforce policy only on NEW findings added after baseline
security-review scan --ci --baseline .security-baseline.json --new-only
```

### Suppressions (`.security-suppress.json`)
A **suppression** is an intentional, permanent exception approved for a false positive or intentional security risk acceptance. Suppressions require explicit rule IDs, target file patterns, and documented audit justifications.

```json
{
  "suppressions": [
    {
      "rule_id": "secret/gcp-api-key",
      "file_pattern": "testdata/mock_key.go",
      "reason": "Synthetic test fixture for unit tests",
      "approved_by": "sec-team"
    }
  ]
}
```
